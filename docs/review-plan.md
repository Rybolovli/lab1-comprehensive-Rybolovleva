# План code-review модуля src/discount.py

## 1. Цели ревью
- Точность расчетов: итоговая цена верна для всех комбинаций скидок.
- Защита от фрода: цена не ниже 70% от суммы корзины, нет отрицательных значений, промокоды не применяются повторно.
- Корректность скидок: порядок применения (базовая скидка, промокоды, уровень лояльности) соответствует требованиям.

## 2. Измеримые критерии
- Отсутствие магических чисел: все пороги и коэффициенты вынесены в именованные константы.
- Валидация входных данных: проверяются cart_sum, tier и promos (100% параметров).
- Покрытие тестами больше 80%.
- flake8 без замечаний (0 ошибок).

## 3. Участники и роли
| Роль | Обязанности |
|---|---|
| Автор кода (Tech Lead) | готовит изменения, отвечает на замечания |
| Ревьюер-разработчик | проверяет логику, читаемость, тесты |
| QA-инженер | проверяет граничные случаи и покрытие тестами |
| Модератор | ведет процесс, принимает решение при спорах |

## 4. Процесс
1. Автор открывает Pull Request в develop.
2. Автоматическая проверка flake8 должна пройти.
3. Ревьюер оставляет замечания в течение 2 рабочих дней.
4. Автор исправляет, ревьюер подтверждает изменения.

## 5. Эскалация при спорах
1. Автор и ревьюер обсуждают замечание в комментариях PR (не более 2 итераций).
2. Если согласия нет, подключается модератор.
3. Если спор не решен за 1 рабочий день, решение принимает руководитель проекта, результат фиксируется в комментарии к PR.
